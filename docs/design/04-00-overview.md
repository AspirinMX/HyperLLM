## 2. 跨任务不变量（任何子任务不得违反）

| 编号 | 不变量 | 归属 |
| :--- | :--- | :--- |
| **T1** | 金额与余额一律 `long` micro-USD，折扣/倍率一律 `int` 基点；`BigDecimal` **只允许**出现在 `payment_orders.fx_rate` 与法币换算的中间量。 | 全阶段 |
| **T2** | 抵扣顺位固定为 **定向资源包 → 赠金批次（过期最早优先）→ 现金**，不允许任何调用方自定义顺序。 | 2.2 |
| **T3** | 实时余额的权威来源是 Redis（Lua 原子扣减）；批次余额的权威来源是 PostgreSQL 批次表；`wallets.*` 是给准入判断与展示用的 O(1) 快照，对账以批次表与账本之和为准。 | 2.2 / 2.4 / 2.9 |
| **T4** | `applicable_models`：`NULL` 表示全部模型；空数组在 DB 层被 CHECK 拒绝；查询**必须**用 `applicable_models @> ARRAY[?]::text[]` 形态，不得用 `= ANY(...)`。 | 2.2 |
| **T5** | 批次剩余量扣减只允许条件原子更新（`WHERE remaining >= ?`），`version` 仅用于 admin 侧编辑的乐观锁，不作为扣减守卫。 | 2.2 / 2.4 |
| **T6** | 幂等键命名：结算 `req:{request_id}`；充值/权益发放 `outbox:{event_id}`；支付下单由调用方提供 `idempotency_key`。 | 2.4 / 2.5 / 2.6 |
| **T7** | Outbox 为 at-least-once；消费端**必须**按 `event_id` 幂等，禁止假设 exactly-once。 | 2.5 |
| **T8** | 网关响应收尾不得被 Kafka 发送或 PG 落库阻塞；结算事件丢失由 2.9 对账兜底，不得因此回滚已下发给客户端的响应。 | 2.3 / 2.4 / 2.9 |
| **T9** | 任何配置表变更必须同时做两件事：控制面提交后主动刷/删 Redis L2 键 + 经 CDC 驱逐各网关实例的 Caffeine L1。只做其一的变更视为缺陷。 | 2.1–2.9 |
| **T10** | 已应用的 Flyway 脚本（V1–V4）不可修改；任何 schema 修正必须以新版本脚本追加。 | 全阶段 |

## 4. 术语对齐

| 术语 | 定义 |
| :--- | :--- |
| **权益批次（entitlement batch）** | `resource_packs`（按单位）与 `bonus_grants`（按 micro-USD）的统称；两者状态机同构，共用 `EntitlementStatus` |
| **预占（hold）** | Redis 中的临时冻结额度，带 `hold_id` 与 TTL 租约，未结算则由回收作业释放 |
| **结算（settle）** | 按实测 Usage 把预占换成实际扣费，并异步发射 `llm.billing.settlement` |
| **现金 / 赠金** | `wallets.cash_balance_micros` 与 `wallets.bonus_balance_micros`；赠金不可提现、不可开票 |

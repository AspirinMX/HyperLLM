## 1. 余额与预算告警

| 规则 | 首次触发依据 | 持续异常 |
| :--- | :--- | :--- |
| 低余额 | Redis 实时快照中的现金与未过期通用赠金，分别扣除对应冻结后求和。可用额小于等于规则阈值 | 重新采样仍命中时，按冷却期提醒。模型限定赠金和资源包按各自的适用范围展示 |
| 项目软预算 | 该 UTC 月的实际已用额达到 Project 的软上限 | 重新采样仍达到上限时，按冷却期提醒 |
| 项目硬预算 | 准入因项目硬预算实际拒绝。记录项目、预算月、额度版本和拒绝时间 | 冷却期内合并同一规则的拒绝。冷却后出现新拒绝时再次提醒 |

预算阈值以 Project 启用的额度为准。首次采样命中后创建投递任务，同一规则默认冷却 60 分钟。月度切换及项目额度版本变更后按新状态判定。钱包或预算状态不可核实时暂缓对应用户告警，并记录采样失败指标。

### 1.1 规则和通知链路

- `console` 的组织管理权限负责低余额规则、项目预算告警和通知端点。确保端点与规则属于同一组织，项目属于该组织。规则引用的端点须有效。端点的停用和投递时状态检查沿同一套规则执行。
- `admin` 运行按批次的规则采样和投递任务。低余额通过实时钱包快照读取。硬预算拒绝在原 Lua 路径更新合并标记。采样作业读取钱包快照和预算信号，网关只记录信号。
- 同一事务内锁规则、检查冷却、登记触发并为各端点写持久任务。任务按触发和端点唯一。多实例以带过期时间的任务领取互斥，提交后再发送邮件或 Webhook。每个端点独立重试、更新结果及保留终止原因。
- Webhook 发送最小必要字段、稳定通知 ID、签名和时间戳。端点使用 HTTPS，发出请求时校验其实际目的地址，禁用重定向并限制连接、响应体和超时。邮件使用配置的 SMTP Adapter。重试保持通知 ID，接收方可按 ID 去重。
- 失败按类型重试，连接错误、429 和 5xx 退避，永久失败或超过重试期限登记终止状态。冷却期按事件创建时间执行，端点重试复用原任务。状态与人工重试操作写审计，日志记录端点 ID 和错误类别。

## 2. 周期性对账

定时作业按组织分批核查。SQL 比对在一致的数据库快照内进行。读取 Redis 钱包与批次时携带镜像代际、结算位置和待确认事件集，核对过程中出现版本变化时重采样。无热镜像的组织使用已确认账务口径，检查现有冷加载门禁对应的证据。

| 检查 | 做法 |
| :--- | :--- |
| 账本与数据库快照 | 分别折叠现金、赠金 delta，与对应钱包快照对照。批次按自身单位核算，记录偏差金额、组织及检查边界 |
| 数据库与 Redis | 按事件身份核对未折叠的 Redis 实扣或发放、已提交的到期和调整，利用原 delta、版本及镜像标识解释差额 |
| 批次与钱包 | 汇总有账面余量的赠金批次，核查钱包赠金快照。记录过期重叠、过渡期虚拟赠金或批次丢失的具体证据 |
| 短缺与回收 | 查看原结算的 `shortfallMicros`、`settledAfterReclaim` 和逐腿明细，解释其计量原因及入账处置 |

有事件 ID 和证据的实扣复用 L1–L4。L1 和 L2 重投已知事件，L3 仅在匹配原镜像和传输门禁时折叠精确 `ADJUST`，L4 保留认亏和迟到事件围栏。认亏后的存活镜像依既有流程继续服务，后续从账本快照冷加载。预算不确定的项目月使用预算恢复门禁。

无逐笔证据的差额持久化为待核对记录，并按严重程度告警。记录携带检查口径、版本边界、关联事件和已确认金额，供运营查证。自动处理的金额以已验证事件 delta 为输入。资金快照、Redis 与 ClickHouse 的观测差额只用于发现异常。

## 3. 最小端到端验收

扩展现有 [Phase 1 联调入口](../../scripts/e2e/README.md) 的实践。使用 Compose 的 pipeline 和 tools 配置，准备测试支付回调、上游流式响应与可观测的邮件及 Webhook Adapter。运行时创建独立测试租户、项目、渠道与规则。以超时有界的轮询等待异步结果，重复执行使用新的测试身份。

| 步骤 | 验收 |
| :--- | :--- |
| 充值、核销、买包 | 签名有效订单或兑换产生唯一授权。等待入账和实时余额可用，重送回调与核销请求 |
| 准入和 SSE | 走实际网关 API。并发预占守住额度，验证抵扣顺序、软硬预算、渠道回退、首帧后断开和回收 |
| 结算和恢复 | 消费者暂停及恢复后，账本、钱包和权益收敛。逐笔注入延迟或缺失，验证 L1–L4 审计及迟到事件围栏 |
| 请求报表 | 使用请求 ID 核对 ClickHouse 事实与按已发布进度的聚合。重投后结果一致，检查权限和 ZDR |
| 告警 | 触发低余额和软硬预算。验证两类端点、冷却合并、失败独立重试以及重放时通知 ID 稳定 |
| Phase 1 回归 | 验证配置 CDC 驱逐、首帧前故障重试、钱包流水持久化 |

交付验收运行 Maven `test`、`verify`、Compose pipeline 配置校验和完整联调脚本。运维验收核对作业 lag、注入异常的告警可达性和对账定位证据。

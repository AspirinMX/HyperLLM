# HyperLLM 网关性能基准测试文档

本目录收录 `hyperllm-gateway` 从原始全 DOM 实现（`V0: 073e2d1`）演进至全链路性能重构最终版（`V4: 9e6d413`）的**全套同口径基准测试、交互式火焰图剖析（CPU / 内存分配 / 锁竞争）、堆存活集审计与双机容量评估**。

> **统一延迟口径（`ΔTTFT`）**：压测上游 `mock-upstream` 故意在首帧前休眠 `500 ms` 模拟真实模型首字推理时间。本套文档中**所有表格与图表的 TTFT 均只记录网关自身引入的净增量 `ΔTTFT = 实测首帧时间 − 500 ms`**，不再混入上游模拟等待时间。

## 核心结论

1. **4C8G 单机配额稳态突破 5,000 并发长流**：
   - 在 **腾讯云 CVM（计算型 C6 | `C6.2XLARGE16`）** 上，网关硬隔离 `4 vCPU`（2 物理核 × 2 HT）/`6 GiB` G1GC 堆，在 **100K-token（401 KB）长上下文输入、2,000 输出 token、200 tok/s** 的典型 Agent 负载下，稳定维持 **5,000 个并发 SSE 连接**（`353.97 RPS`、`141,941 帧/s`、`0 错误`、`ΔTTFT` P50 `+216.6 ms` / P99 `+603.7 ms`、老年代仅 **`244 MB`**、**0 Full / 0 Mixed / 0 Concurrent GC**）。
   - 在 **Hetzner Cost-Optimized `CAX 31`（ARM64）** 上，网关硬隔离 `4 vCPU` / `5 GiB` 堆，同/跨协议均稳定跑通 **3,500 并发 SSE 连接**（`304.72 RPS`、`122,191 帧/s`、`0 错误`、老年代仅 **`134–144 MB`**、**0 Full / 0 Mixed / 0 Concurrent GC**）。
2. **保留 Canonical IR 的同时实现 36× 单流常驻内存缩减**：
   - 所有请求统一经过 `downstream → Canonical IR → Normalizer → upstream`（安全边界 + 4×4 协议无损互通 + 重试窗口内可换协议重试）；
   - 通过 **6 轮火焰图驱动重构**，3,000 并发稳态强制 Full GC 后的真实存活集从 **2,741.4 MB（V3）** 降至 **154.3 MB（V4）**；单流常驻堆内存从 **~1,265 KB/流（V0）** 暴降至 **~35 KB/流（V4，缩减 36×）**，跨协议与同协议性能完全持平。
3. **内存分配、GC 与业务锁全面归零级压缩**（ARM64 跨协议 `c1000 / c2000` 同口径对比）：
   - 15s 稳态内存分配样本（`asprof -e alloc` @ `cross c1000`）：**`14,160`（V0）→ `2,941`（V4，−79.2%）**；
   - `cross c2000` 90s 总 GC 停顿：**`4,316 ms` / 115 YGC（V0）→ `239 ms` / 5 YGC（V4-G1，−94.5%）→ `0–1 ms`（V4-GenZGC）**；
   - `cross c3000` 90s 总 GC 停顿：**`6,094 ms` / 112 YGC + 4 Full GC（V3）→ `487 ms` / 8 YGC + 0 Full GC（V4-G1，−92.0%）**；
   - V4 在 `c2000` 下业务代码锁竞争为 **0**，网关 CPU 中 **82.5%** 用于纯网络收发与事件循环，整套 IR + 跨协议编解码仅占 **9.2%**。
